# Attribution

The 40 task files in this directory (`HE-NNN.json`) and the reference solutions in `../reference/` are
translations of problems from the HumanEval dataset, with hidden test cases taken from HumanEval+:

> Mark Chen, Jerry Tworek, Heewoo Jun, et al. *Evaluating Large Language Models Trained on Code*.
> arXiv:2107.03374, 2021. https://github.com/openai/human-eval

HumanEval is distributed under the MIT License, Copyright (c) OpenAI. The `source` field of each task names
the original problem (`HumanEval/<number>`). The English statements are rewritten without code; the hidden
test cases come from HumanEval+ (see below); they include the original HumanEval tests. The Aval and Rust reference solutions are original work.

## HumanEval+ (EvalPlus)

The hidden cases (field `hidden`), the tolerance (`atol`) and their provenance (`source_tests`, `excluded`) are
generated by `../tools/import_humaneval_plus.py` from the HumanEval+ tests of EvalPlus:

> Jiawei Liu, Chunqiu Steven Xia, Yuyao Wang, Lingming Zhang. *Is Your Code Generated by ChatGPT Really
> Correct? Rigorous Evaluation of Large Language Models for Code Generation*. NeurIPS 2023.
> https://github.com/evalplus/evalplus, data: https://huggingface.co/datasets/evalplus/humanevalplus

EvalPlus and the HumanEval+ dataset are distributed under the Apache License 2.0
(https://www.apache.org/licenses/LICENSE-2.0). Only the cases that map to Aval's types are kept; the
others are counted per reason in `excluded`. The EvalPlus data file itself (`test.jsonl`) is not part of this
repository and the importer reads it from a path given on the command line. The importer takes the
tolerance rule of EvalPlus's `assertion` helper (`atol` 1e-6 for float results when none is declared) and changes
nothing else in the data except where `excluded` says so.

Notes:

- The harness follows EvalPlus's comparison, `abs(got - expected) <= atol + 1e-7 * abs(expected)` (numpy
  `assert_allclose` with `atol` and the default `rtol` of 1e-7); with `atol` 0 the comparison is exact.
- HE-027 (`flip_case`) keeps only 257 of 975 cases: most HumanEval+ inputs contain non-ASCII characters that
  Aval strings cannot express, so the task no longer discriminates Unicode case handling.
- Cases that a natural (recursive) Aval solution cannot handle within the interpreter's limits (10 million
  steps per case, recursion depth 10,000) are excluded with reason `budget` for HE-015, 025, 031, 036, 049
  and 056; the rule is documented in `../tools/import_humaneval_plus.py`.

## MBPP and MBPP+ (task set `tasks-mbpp/`)

The tasks `MB-NNN.json` in `../tasks-mbpp/` are generated by `../tools/import_mbpp_plus.py` from MBPP+ (EvalPlus,
Apache-2.0, https://huggingface.co/datasets/evalplus/mbppplus, revision b2d74c91837c3f2a20c1299ae98133cbe7cfa077)
which extends the MBPP benchmark:

> Jacob Austin, Augustus Odena, Maxwell Nye, et al. *Program Synthesis with Large Language Models*.
> arXiv:2108.07732, 2021. https://github.com/google-research/google-research/tree/master/mbpp
> MBPP is licensed under CC BY 4.0 (https://creativecommons.org/licenses/by/4.0/).

> Jiawei Liu, Chunqiu Steven Xia, Yuyao Wang, Lingming Zhang. *Is Your Code Generated by ChatGPT Really
> Correct? Rigorous Evaluation of Large Language Models for Code Generation*. NeurIPS 2023.
> https://github.com/evalplus/evalplus (Apache License 2.0).

Each task statement is the MBPP problem text with one added `Example:` line taken from the first retained MBPP+
case; the hidden cases are the other MBPP+ cases whose values map to Aval's types (changes: type inference,
snake_case names, exclusions counted per reason in `excluded`). The Aval and Rust reference solutions in
`../reference-mbpp/` are original work. The dataset file itself is not part of this repository.
